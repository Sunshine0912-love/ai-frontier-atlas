# AI Frontier Atlas 双更维护手册

## 边界

本项目是独立网站，仓库固定为 `/home/xujiaz/ai-frontier-atlas`，远端固定为 `Sunshine0912-love/ai-frontier-atlas`。不得修改、发布或复用 `/home/xujiaz/xiaoguang-blog` 的页面、索引、文章和自动任务；旧博客有自己的确认式选题流程。

## 强制顺序

每次 09:00/21:00 维护严格执行：

```text
回顾当前网站 → 写本轮计划 → 研究/编辑 → 测试验证 → 发布 → 记录下一方向
```

在完成回顾与计划前，禁止修改 `src/data/`、`src/pages/`、组件或样式。

## 1. 回顾当前网站

1. 检查 git 状态与远端，不能覆盖无关改动。
2. 阅读首页、前沿页、学习页、方法页。
3. 阅读 `src/data/frontier.json`、`tracks.json`、`syllabus.json`、`lessons.json` 和 `articles.json`，核对研究域映射、四维评分、课程深度、完整目录和先修关系。
4. 阅读 `ops/site-review.json` 和最近两份 `ops/logs/*.md`。
5. 运行 `npm ci`（依赖未安装时）和 `npm run review:site`。
6. 回答：最近更新是什么、哪些主题重复、哪些路线为空或陈旧、哪些来源/结论需要复查。

## 2. 先写计划

创建 `ops/logs/YYYY-MM-DD-HHMM.md`，先填写：

- 当前内容回顾
- 本轮班次与目标
- 计划动作和选择理由
- 明确不做
- 来源与验收标准

写完计划才开始编辑。单轮默认最多新增 3 条前沿信号或 1 节完整课程。

## 3. 09:00 前沿班次

- 研究过去约 12 小时，必要时扩展至 72 小时内刚出现可靠一手资料的进展。
- 使用 `agent-reach` 搜索并直接核对论文、官方博客、技术报告、源码、模型卡、评测仓库和监管文件。
- S 级原始证据优先；A 级可靠解释用于补充；B 级媒体/社区只用于发现线索。
- 每条必须填写 `fact`、`mechanism`、`impact`、`uncertainty`、`watchNext`、四维评分和至少一个直接来源。
- 四维评分为 1–5 分：新颖性、影响、证据强度、可复现性。它是编辑判断，不能写进事实字段。
- 明确区分事实、推断和判断；不发布只有自报榜单、没有方法细节的营销信息。

## 4. 21:00 学习班次

- 根据 `trackCoverage` 和依赖关系选择下一课，不根据热搜选择。
- 每课必须有学习目标、先修知识、问题设定、基线、至少两个公式及逐项解释、最小例子、张量/源码路径、复杂度或性能分析、工程决策、失败边界、动手实验、自检问题和至少三个可靠来源。
- 新课必须先进入 `syllabus.json` 的正确依赖位置，再将状态从 `planned` 改为 `available`；不得为追逐热点破坏课程顺序。
- 正文论述不少于 1800 个中文字符，必须是连续解释而非扩写后的项目符号；正文使用 17px/1.9 行高，任何辅助文字不得小于 12px。
- 公式/张量/源码细节不足时不写成定论；无法达到课程质量时改做补源、纠错或路线维护。
- 优先填补空路线，再扩展已有路线；保持由浅入深。

## 5. 验证与发布

依次运行：

```bash
npm test
npm run review:site
npm run check
npm run build
npm run verify:build
npm audit --audit-level=high
```

所有命令通过后，补全本轮日志的“实际执行、验证结果、发布结果、下一方向”。只提交本项目文件，推送 `main`，检查 GitHub Actions 和线上 URL。失败时不推送，记录真实失败与下一步。

## 6. 结果通知

向用户微信发送一条完整中文报告，包含回顾、计划、实际变更/无更新原因、测试构建部署、链接与 commit、下一轮方向。禁止发送半成品。
